## Corrections to the prior assessment

The brief was wrong on the two most load-bearing points. Both were checked
empirically.

### "Blocked on greta 0.6.0 rank-3 batching (`tf$tile`)" — false

There is no `tf$tile` call anywhere in PR #9, and none in greta's R source
either (`grep -rn 'tf\$tile' R/` in `greta-dev/greta` returns only
`tf_functions.R` internals unrelated to this path). Multi-chain MCMC — which is
exactly what exercises the rank-3 batch dimension — works fine once the two real
bugs below are fixed. Verified with `chains = 2` on a 200-site, K=4 occupancy
model; posterior means recover the truth.

This was answer **(c), a misdiagnosis**, not (a) or (b). Nothing needs to change
upstream in greta.

### "PR #10 just needs its dimension contract decided" — badly understated

PR #10's `tf_distrib` opens with a literal `stop("not implemented")`. Everything
after it is pseudocode:

- `N_pos`, `N_neg`, `idx_pos`, `idx_neg`, `idx_pos_list`, `idx_neg_list` are
  referenced but never assigned
- `z` is passed to `tf_replace(z, ...)` before it exists
- `mu` is referenced; the local is named `mean`
- `bound_pos` / `bound_neg` are referenced; only `bound_pos_k` / `bound_neg_k`
  are defined
- `u_pos_k` is assigned twice, the second time from the *negative* index (a
  copy-paste bug), so `u_neg_k` is never defined
- `tf$cholesky` and `tf$log` were removed in TensorFlow 2 (`tf$linalg$cholesky`,
  `tf$math$log`). Confirmed: `tf$cholesky` raises `AttributeError` here.
- `lj_pos[, k] <- tf$log(...)` is R-style subassignment into a TF tensor, which
  is not possible in TF2
- the function returns a single scalar (the summed log-Jacobian), not one
  density per realisation
- `sample` is absent from the returned list

The dimension contract was the *first* error a caller hit, not the only one. The
PR is a design sketch, not an implementation. I rewrote the density from
scratch.

### Smaller correction

PR #9 does **not** need "a one-line signature fix to get it constructing" — it
constructs unmodified. The signature problem (`tf_distrib = function(parameters)`
vs greta 0.6.0's `tf_distrib(parameters, dag)`) surfaces at *density evaluation*
time, as `unused argument (dag = self)`.

## PR #9 — conditional Bernoulli

**Verdict: shippable now.**

The maths in the PR was right. Three bugs, all now fixed.

### Bug 1 — `tf_distrib` signature (blocking)

greta 0.6.0 calls `distrib_constructor(tf_parameter_list, dag = self)`
(`dag_class.R:396`). The PR declared `tf_distrib = function(parameters)`.
Fix: add the `dag` argument.

### Bug 2 — missing `multivariate = TRUE` (silent wrong answer)

This is the important one, and it is the bug the prior assessment mistook for a
batching problem.

`super$initialize()` was called without `multivariate = TRUE`. In
`node_types.R:521`, `expand_parameter()` branches on `self$multivariate`:

- multivariate `TRUE`: a *row* parameter is `rbind`-replicated up to
  `n_realisations` rows
- multivariate `FALSE`: a *scalar* parameter is expanded to the full `dim`,
  here `c(dim, K)`

Because the conditional Bernoulli is genuinely multivariate (each realisation is
a length-K binary vector), leaving the flag `FALSE` meant a scalar `psi` was
expanded to a `dim x K` array. The density then broadcast back out to K columns,
so `greta_density()` returned **K identical copies of each row's log density**.
`define_gradients()` calls `tf_sum` over that, so the log likelihood was silently
multiplied by K.

Observed directly: with `p = matrix(c(0.1, 0.9), ncol = 2)`, `psi = 0.9`,
`x = matrix(c(1, 0), ncol = 2)`, the density returned
`c(-4.710531, -4.710531)` instead of the single correct value `-4.710531`.

This would not have been caught by any of the PR's six snapshot tests, all of
which are argument-validation errors.

### Bug 3 — probability check rejects greta arrays (blocking for inference)

`check_valid_probability()` ran `any(x < 0) | any(x > 1)` on the *raw* argument,
captured before coercion. Passing a greta variable (`beta(1, 1)`) — i.e. the
entire point of the distribution — produced

```
Error in if (any(x < 0) | any(x > 1)) : missing value where TRUE/FALSE needed
```

so `p` and `psi` could only ever be fixed numeric data. Fixed by returning early
for `greta_array` / `node` inputs; the constraint is enforced by the supplied
variable's own support instead. Numeric literals are still range-checked.

### Added

`sample` was `NULL`, so `calculate(cb, nsim = n)` failed with "Sampling is not
yet implemented". Implemented the obvious ancestral sampler: draw
`z ~ bernoulli(psi)`, then `y ~ bernoulli(z * p)`, using a separate seed stream
for `y` so the two draws are not deterministically tied.

### Verification

Reference: the MacKenzie et al. (2002) occupancy density written directly in
plain R. Checked at 1 row, 5 rows with per-row parameters, all-zero rows (the
`(1 - psi)` branch), and single-row parameter recycling — agreement to 1e-16.
Enumerating all 2^K outcomes gives densities summing to 1. The sampler's
empirical outcome frequencies match the analytic pmf to 0.0018 over 20 000
draws. Two-chain MCMC on a 200-site K=4 occupancy model recovers `psi` and `p`.

## PR #10 — multivariate probit

**Verdict: shippable now, but the density is a simulated likelihood — see the
caveat below.** The PR's own code was discarded and replaced.

### The dimension contract

Decided, not guessed, by reading `multivariate_normal_distribution` in
`greta-dev/greta:R/probability_distributions.R:862` and
`check_multivariate_dims()` in `R/checkers.R:487`.

**greta's convention for multivariate distributions is `n_realisations x
dimension`: rows are realisations, columns are the K dimensions.** `mvn`'s
`mean` is a `1 x K` row vector (or `n x K`); `Sigma` is `K x K`.

The multivariate probit therefore takes:

- `mean`: `dim x K`, or `1 x K` recycled across realisations. **A row vector,
  not a column vector.**
- `C`: `K x K` **correlation** matrix (unit diagonal — the scale of the latent
  normal is not identified by binary data, so a general covariance matrix is
  rejected with an explanatory error)
- output: `dim x K`
- `multivariate = TRUE`, `discrete = TRUE`

PR #10 had this backwards — it required `ncol(mean) == 1`. So the error quoted in
the brief (`mean must be… one column, but has dimensions 1 x 2`) was the PR
rejecting the *correct* greta-convention input. Its own test passed a `2 x 1`
column and did construct; it failed later, inside `calculate`.

### Why the PR's architecture could not work as written

Beyond the pseudocode, PR #10 added a free `u <- variable(0, 1, dim = self$dim)`
as a distribution *parameter* — an auxiliary latent uniform for a GHK-style
data-augmented likelihood. greta cannot sample a target whose parameters include
a variable with no distribution:

```
the target <greta_array>s are related to variables that do not have
distributions so cannot be sampled
```

That is what its one live test actually hit — not the dimension check.

### Replacement implementation

The multivariate probit density is an orthant probability of the latent MVN,
which has no closed form for K > 2. Confirmed there is no shortcut in this stack:
`tfp$distributions$MultivariateNormalTriL$cdf()` exists but raises
`NotImplementedError: _is_increasing not implemented in ScaleMatvecLinearOperator`.

Implemented the Geweke-Hajivassiliou-Keane (GHK) simulator directly in
TensorFlow. For observation `y`, let `s = 2y - 1` and `w = s * z`; then
`P(y) = P(w > 0)` with `w ~ N(s * mean, D C D)`, `D = diag(s)`. GHK factorises
this along the Cholesky factor of `D C D`, drawing each latent from a truncated
normal and accumulating the product of conditional probabilities.

Key design choice: the draws are a **fixed Halton sequence** generated once in
`initialize()` and stored on the R6 object. This makes the log density a
deterministic, smooth, differentiable function of `mean` and `C`, which is what
gradient-based samplers require. A fresh random draw per evaluation would break
HMC. `n_sim` (default 200) controls accuracy.

`sample` draws the latent MVN and thresholds at zero.

### Verification

Reference: `mvtnorm::pmvnorm` (Genz-Bretz quasi-Monte Carlo).

- K=2, all four outcomes: max abs error 8e-4 in log density; probabilities sum
  to 1
- K=4 correlated, six outcomes: max abs error 4.7e-3
- K=3 with per-realisation means: max abs error 3.0e-3
- Convergence in `n_sim` (the test that shows the estimator is consistent, not
  biased): 50 → 0.032, 200 → 0.017, 1000 → 0.0046, 4000 → 0.0020. This is the
  expected O(1/sqrt(R)) GHK rate.
- Determinism: two evaluations at the same `n_sim` are bitwise identical
- Sampler vs analytic pmf: max abs error 0.0036 over 20 000 draws
- MCMC: 400 observations, true correlation 0.6, `lkj_correlation(2, dimension = 2)`
  prior, two chains — posterior mean correlation **0.593**

### Caveat to flag to the maintainer

Unlike every other distribution in this package, this density is **approximate**.
The error at the default `n_sim = 200` is ~0.02 in log density per observation.
That is fine for inference on the correlation structure (demonstrated above) but
it is not an exact likelihood, and users summing over many observations should
raise `n_sim`. This is documented in the roxygen block. If the maintainer would
rather not ship an approximate density at all, that is a legitimate call — but
the alternative is not shipping a multivariate probit, since the orthant integral
has no closed form.

## Testing standard

Every test written here checks numerical correctness against an independent
reference (plain-R MacKenzie density for #9, `mvtnorm::pmvnorm` for #10). No
`compare_distribution()` block was left commented out, and no test asserts only
that something ran without error.

The pre-existing snapshot tests for argument validation were kept and extended,
but they are now a minority of the suite rather than the whole of it.

`mvtnorm` is used by the PR #10 tests and needs to be in `Suggests`. **I did not
add it — `DESCRIPTION` was off-limits.** The coordinator should add it.
